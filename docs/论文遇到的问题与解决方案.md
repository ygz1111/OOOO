## 问题1：预测精度不足（MAPE 9~10%）<a name="问题1"></a>

### 现象

系统上线后，大屏显示"历史 24h 回测"的 MAPE 约 **9~10%**，明显高于训练阶段测试集报告的 **7.4%**。预测曲线与实际负荷曲线在部分时段偏差较大。

### 排查过程（按可能性排除）

1. **特征一致性检查**：逐一对比训练侧（`step6_pipeline_config.pkl`）与推理侧（`feature_generator.py`）的 38 维特征，名称与顺序 **100% 一致**；训练管道将气象原始数据（华氏度）转换为摄氏度后入模，推理侧 Open-Meteo 直接提供摄氏度，单位一致；MinMaxScaler 训练参数由推理侧复用、不重新拟合，无归一化泄漏。
2. **时间对齐检查**：梳理 Open-Meteo API 时间、ISO-NE 负荷时间、数据库时间、模型输入时间、前端显示时间，全链路统一为**新英格兰墙钟时间（America/New_York，naive）**，无 UTC/8 小时/1 小时偏移。
3. **数据粒度检查**：训练数据与 API 返回均为 1 小时粒度，一致。
4. **数据源对比实验**：发现历史回测使用的"历史气象"来自天气预报 API 的 past_days 参数（**历史预报值**），而非实际观测/重分析数据。

### 根因（两个）

| 根因 | 说明 |
|------|------|
| **① 历史气象口径不一致** | 训练时使用真实历史气象（NOAA/重分析），回测时使用"历史天气预报值"。实测对比：预报与重分析的温度平均差 0.65°C、云量差 30%。 |
| **② 历史负荷输入被污染** | 数据库真实负荷覆盖不足（192 小时窗口缺 23 小时，含整天缺失），缺口用**训练数据时间戳重映射**填补——把 2023~2024 年某天的负荷模式当作最近一天使用，与真实负荷相差可达数千 MW，严重污染 lag_168、rolling_168 等滞后特征。 |

### 解决方案

1. **历史气象切换为 Archive（ERA5 重分析）API**：`Open-Meteo Archive API` 免费、无需 key，返回与训练数据口径一致的历史重分析数据；今天未归档的小时用预报数据补齐。
2. **真实负荷补全**：ISO-NE 实际负荷同步任务由"拉取 2 天"改为"拉取过去 14 天"，保证 192 小时输入窗口全部为真实值；缺口处理由"训练数据重映射"改为**相邻真实值前向填充（ffill）**，训练数据回退仅作为完全无数据时的最后手段。

### 量化效果（同一 24h 回测窗口、同一模型、单因素实验）

| 方法 | MAE (MW) | RMSE (MW) | MAPE |
|------|----------|-----------|------|
| ① 优化前（现状） | 1049.7 | 1414.9 | 6.18% |
| ② 仅切换 Archive 历史气象 | 969.2 | 1390.4 | 5.59% |
| ③ 仅补全真实负荷 | 988.2 | 1286.7 | 5.92% |
| ④ 优化后（②+③） | **907.8** | **1259.2** | **5.29%** |
| **总改善** | **-13.5%** | — | **-0.90pp** |

线上 overview 端点实测由 **9.85% 降至 6.15%**（同时消除了训练数据重映射污染）。

> 说明：残余误差主要来自 ① 模型训练数据截止 2025 年底（未含 2026 年数据）；② 未来预测必须使用天气预报（预报误差传导）；③ 白天时段（早高峰、温度骤变）预测难度天然高于凌晨。

## 问题2：历史回测指标失真：预测与实际错位 1 小时 <a name="问题2"></a>

### 现象

历史回测的 MAE/MAPE 指标系统性偏低（"虚好"），但逐点核对发现预测曲线与真实曲线整体错位约 1 小时。

### 排查方法

对训练序列数据 `step6_sequences.pkl` 做**数值级验证**：取测试样本，将模型输出第 0 小时反归一化（11502 MW），与输入窗口滑动 2 步后的 `load_lag_1h` 特征反归一化值对比，**两者完全相等**，证明**模型第 0 个输出对应"输入窗口末时刻 + 1 小时"的负荷**。

### 根因与修复

回测代码将"输入窗口截止 t 时刻"的模型输出直接与 **t 时刻**的真实负荷对比，存在 1 小时错位。修复为：预测值对齐 **t+1 时刻**的真实负荷（`prediction_insight.py`）。

### 效果

回测指标恢复真实水平，最后一个回测点的预测值与"当前实际负荷"完全吻合（数值一致验证通过）。

## 问题3：特征输入"预测值喂预测"：滞后特征失真 <a name="问题3"></a>

### 现象与根因

模型输入包含 17 维负荷滞后/滚动/差分特征（load_lag_1h/24h/48h/168h 等）。原实现中，当数据库无真实负荷时，使用**模型自己的历史预测值**作为这些特征的输入——形成"用猜的结果去猜新的结果"的闭环，误差沿滞后特征逐小时累积，且与训练阶段（使用真实负荷）的分布不一致。

### 解决方案

1. 特征输入的数据源优先级改为：**ISO-NE 真实负荷（actual_load_data 表）> 历史预测值（仅补缺口）> 训练数据冷启动**；
2. 后台每 60 分钟自动同步 ISO-NE 真实负荷，保证滞后特征基于真实值计算。

## 问题4：集成权重设置不合理 <a name="问题4"></a>

### 现象

四模型集成权重初版为人为设定（EnhancedLSTM 0.35 / BiGRU 0.30 / DeepTCN 0.15 / SpatialTransformer 0.20），但测试集评估显示 **SpatialTransformer 精度最高（MAE 586）权重却最低（0.20）**，集成结果（MAE 986）反而差于最佳单模型。

### 解决方案

编写权重重算脚本（`scripts/recompute_ensemble_weights.py`），在**验证集**（2025-01~09，6552 样本）上评估四个模型，按**反误差加权**（w ∝ 1/MAE）重算权重：

| 模型 | 旧权重 | 验证集 MAE | 新权重 |
|------|--------|-----------|--------|
| EnhancedLSTM | 0.35 | 1246 | 0.2412 |
| BiGRU | 0.30 | 1603 | 0.1875 |
| DeepTCN | 0.15 | 1711 | 0.1757 |
| SpatialTransformer | 0.20 | **760** | **0.3956** |

集成 MAE 由 **1219 → 1053（-13.7%）**。使用验证集而非测试集调参，避免数据泄漏；权重来源可完整复现（结果文件 `ensemble_weights_recomputed.json`）。

## 问题5：时区错位：图表小时轴整体偏移 12 小时 <a name="问题5"></a>

### 现象

后端统一返回"新英格兰墙钟时间"（naive，无时区后缀），前端用 `new Date(iso)` 解析时，浏览器按**本地时区（中国 CST）**解释这些时间，导致图表小时轴整体偏移 12 小时、"当前"标记与真实时刻完全错位。

### 解决方案

1. 前端新建时间工具模块（`utils/time.ts`）：将 naive ISO 解析为 **America/New_York** 真实时刻（自动处理 EST/EDT 夏令时），全部 12 处时间显示（图表、表格、页头、登录页、历史分析）统一按 ET 格式化；
2. 页头时钟、登录页横幅标注"ET"，删除"中国时间（CST）"展示。

### 效果

图表"当前"参考线、X 轴小时偏移、数据点时间标签与真实时刻完全一致。

## 问题6：启动阶段"数据异常"误报 <a name="问题6"></a>

### 现象

后端启动需加载 4 个深度学习模型（约 20~30 秒），期间前端显示红色"数据加载异常"；且一旦某个数据源先成功，其余未成功的服务失败就会被误报为异常，直到下一个 5 分钟轮询周期。

### 解决方案

1. **按服务独立抑制**：每个数据源"从未成功过"时的失败静默重试；仅"曾经成功、之后失败"才报错；
2. 启动期显示中性的"正在连接后端服务…"状态；
3. 失败后每 20 秒自动重试直至恢复；
4. 预测接口超时由 30s 放宽至 90s（冷缓存时气象 API 拉取 + 推理可能超 30s）。

## 问题7：浏览器资源 404 与外部字体无法访问 <a name="问题7"></a>

### 现象

控制台持续出现 `Failed to load resource: 404`，来源为：① 页面未定义 favicon，浏览器自动请求 `/favicon.ico`；② `index.html` 外链 Google Fonts，国内网络无法访问。

### 解决方案

1. 内联 SVG favicon（不再产生请求）；
2. 移除 Google Fonts 外链，回退系统字体栈。

---

## 问题8：数据库重复数据膨胀与建表缺失 <a name="问题8"></a>

### 现象与根因

1. 气象数据、预测结果表**无唯一键**，每 5 分钟轮询 × 6 站点、每次预测 24 条记录重复插入，数据持续膨胀；
2. `actual_load_data`（实际负荷表）在初始化 SQL 中缺失，全新部署会失败。

### 解决方案

1. 表结构增加唯一键（`(location, timestamp)` / `(prediction_id, target_timestamp)`），写入改为 `INSERT ... ON DUPLICATE KEY UPDATE` / `INSERT IGNORE` 幂等模式；
2. 补齐 `actual_load_data` 建表语句（含唯一键），并提供对已存在表的去重迁移存储过程。

## 问题9：实时预测接口响应慢、前端控件失效 <a name="问题9"></a>

### 现象

1. overview 接口每次请求执行 24 次模型回测推理 + 2 次气象拉取（约 3~10s），前端多页面轮询导致超时、页面空白；
2. 负荷预测页"时间范围""模型切换"两个下拉框选中后**不触发任何行为**（死控件）。

### 解决方案

1. overview 结果增加 **60 秒 TTL 缓存**（实测：未缓存 2.67s → 命中 0.015s）；
2. 后端返回各模型单独预测字段（模型推理服务本就输出 `individual_predictions`），前端模型切换**真实生效**（曲线数据随选择变化）；时间范围改为前端真实切片（历史 6h/12h/24h 回看）。

## 问题10：前端"假数据"展示问题 <a name="问题10"></a>

### 现象

1. 系统状态页"最后推理/最后更新"用 `new Date()` 渲染时时间，永远显示"现在"（假时间戳）；
2. 模型数"4/4"硬编码；"WebSocket: 待实现"占位；推理进度条固定 60%（装饰假数据）；
3. 光伏页参数卡片硬编码；功率曲线接口失败时卡片凭空消失无提示。

### 解决方案

1. 假时间戳改为真实数据（系统状态接口返回的时间戳、真实推理计数）；
2. 模型总数由后端返回（`models_total`）；"WebSocket 待实现"改为真实的"REST 轮询（5 分钟）"；
3. 进度条改为真实推理速率（总推理次数 ÷ 运行时长）；
4. 光伏参数卡数值取自模型信息接口（未加载时保留文档口径回退）；功率曲线失败显示错误提示 + 重试按钮。

## 问题11：光伏预测单位换算澄清与回归保护 <a name="问题11"></a>

### 现象

光伏 ML 模型训练数据为单站 500 kWp PVLib 仿真（输出峰值约 480 kW，单位 kW），部署口径为 500 MW 装机（单位 MW）。代码中换算系数的**注释与实现不一致**，且换算依据不直观，存在被误改导致量纲放大 1000 倍的风险。

### 处理

1. 数值级验证：`target_scaler.data_max_ = 480`（kW），`scale_factor = 500 MW / 480 kW ≈ 1.04` 已隐含"容量比 ÷ 1000"两项换算，**数值行为正确**（满发输出 500 MW，与物理模型一致）；
2. 将魔法系数改写为**自文档化公式**并注明"切勿改为 1042"；
3. 新增**量纲回归测试**（4 个用例）：锁定满发峰值必须落在物理合理区间（300~520 MW），防止后续修改破坏量纲。

## 总结：问题—方法—效果对照表 <a name="总结"></a>

| # | 问题 | 方法 | 量化效果 |
|---|------|------|----------|
| 1 | 预测精度不足（MAPE 9~10%） | 历史气象切换 ERA5 重分析 + 真实负荷补全 + ffill 补缺 | 回测 MAPE 6.18%→5.29%（线上 9.85%→6.15%） |
| 2 | 回测指标错位 1 小时 | 序列数据数值验证 → 对齐修正 | 指标恢复真实，逐点吻合 |
| 3 | 预测值喂预测 | 真实负荷优先 + 14 天同步 | 滞后特征基于真实值 |
| 4 | 集成权重不合理 | 验证集反误差加权重算 | 集成 MAE 1219→1053（-13.7%） |
| 5 | 时区错位 12 小时 | 前端统一 America/New_York 解析 | 图表时间轴完全对齐 |
| 6 | 启动期数据异常误报 | 按服务独立抑制 + 自动重试 | 启动期无红色误报 |
| 7 | 404/外部字体 | 内联 favicon + 移除外部字体 | 控制台无资源错误 |
| 8 | 数据库膨胀/缺表 | 唯一键 + 幂等写入 + 补建表 | 数据不再重复插入 |
| 9 | 接口慢/死控件 | overview 60s 缓存 + 单模型字段 | 0.015s 命中；控件真实生效 |
| 10 | 前端假数据 | 真实时间戳/模型数/速率条 | 展示数据全部真实 |
| 11 | 光伏量纲风险 | 自文档化公式 + 回归测试 | 量纲永久锁定 |

**系统最终状态**：后端 261 个自动化测试全部通过；历史回测（历史气象→模型→预测→与真实负荷对比）与未来预测（未来天气→模型→24h 预测，不使用未来真实负荷）逻辑严格分离，无数据泄漏。
