# 本地运行：数据对齐与刷新优化

后续以本机运行作为交付方式；不继续云服务器部署、不更新旧服务器压缩包。
保留 ISO-NE 和现有 TensorFlow 权重，不训练、不升级依赖、不清空数据库。

## 本轮修正

1. 统一在线输入和后台实测同步：八个负荷区的小时均值求和，负荷以小时结束标记。
   例如美东 09:40，09:00 对应 08:00–09:00；09:00–10:00 尚未结束，不能保存为完整实测。
   光伏独立数据按小时开始标记，合并图在同一区间结束时间对齐。
2. 五分钟数据按“区间时间＋负荷区”去重，排除无穷值、非数字、负负荷、错位采样。
   每区至少8次有效采样可作为带提示的模型输入；8区各12次采样才可保存为完整小时评价标签。
   不完整负荷不显示成最近完整实测，不完整负荷/光伏不作为回溯误差标签。
3. 新实测使用 `region=NewEngland_zonal_HE`、`data_source=iso_ne_zonal_he_v2` 独立保存，
   利用现有区域字段隔离口径，不修改表结构、不覆盖旧记录。新在线预测标记 `zonal_he_v2`。
   准确率查询按目标时间关联新口径标签，不再信任旧 `load_predictions.actual_load_mw` 的混合回填值。
   EIA/旧系统负荷继续保留作存档，不混入当前模型评价。
4. 新模型输出必须是24个连续、正确对齐的小时；重复、错位、缺点、非有限值、倒置电价分位数会被拒绝。
   失败只降级对应模块，仍沿用之前经过验证且未过期的结果，不改旧预测的生成时间。
5. 历史回测按输入内容缓存，不再因请求复制了对象就重复进行24次推理。
   输入/标签修订时重新计算；显式按日强制刷新仍可重新推理。
6. 手动刷新先更新共享预测，再绕过图表自身缓存读取结果；不再仅刷新天气却留下旧预测。
   统计接口遇到带 UTC/时区偏移的时间，先换算美东时间，再去掉时区供本地数据库对齐。
7. 运行态势页也改用有等待上限的共享预测，不再提前另取天气。
   缺光伏时保留负荷、净负荷留空；不把部分光伏相加冒充完整区间总电量，不跨缺口计算爬坡。
   保留原始预测生成时间；跨整点失效旧缓存，页面隐藏过期曲线和派生统计，准备中35秒后重试。

## 验证

- 后端选定回归测试：103项通过，涵盖采样去重、缺区、非法数值、当前小时、跨日、跨整点、模块独立失败、缓存、运行态势与历史统计。
- 前端测试：28项通过；类型检查和生产构建通过。新增运行态势空值显示、跨整点统计失效、准备中快速重试测试。
- 使用本地已有真实模型权重配合合成在线输入验证推理链；未训练模型。
- 此轮测试不访问真实外部接口、不启动项目服务、不读写真实数据库。
- 数据库查询除模拟调用外，在临时内存数据库执行实际SELECT，验证新旧标签隔离且旧值不改变。
  本机项目和数据库未发现相应监听端口，未擅自启动；真实 MySQL 联调、真实网络耗时和浏览器视觉验收仍未进行。

## 本地使用时的变化

继续使用项目根目录的 `start.ps1` 启动本地项目。前端代理指向本机8000端口，不需要云服务器。
本轮没有替用户启动项目，也没有修改任何云资源。

下次启动时，现有后台任务会同步近期官方数据到新口径分区。首次仍可能需要等待官方接口。
旧在线预测不会被自动改成新口径，因此在线准确率可能暂时无数据：待新预测对应小时结束、完整官方数据到齐后逐步恢复。
历史回溯验证与在线准确率不是同一个指标，不能互相替代。

## 仍需注意

- 采样齐全不代表官方最终结算值；官方分区接口本身是估算/实况汇总口径。
- 旧数据未删除，也没有盲目平移旧时间戳。更早的历史资料需要按新口径重新获取，不能直接复用旧评价标签。
- 原模型和数据库仍使用美东无时区偏移的小时键。夏令时回拨重复小时无法唯一表示，本轮保守排除歧义小时，
  不把两小时混成一小时；完整支持每年的23/25小时日仍需独立改造，届时可能因严格缺口检查而降级。
- 缺数据时“昨日同时段补输入”的预测精度尚未独立验证；已有前端提示，不能据测试通过声称精度提高。
- 本地运行仍需访问天气、电网数据源；外部断网或发布延迟不会因为取消服务器而消失。
- 云服务器是否仍计费需在云平台另行确认；本地代码修改不等于停止/释放云资源。
