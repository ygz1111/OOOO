# 项目稳定性检查与 GitHub 发布（2026-10-07）

本轮在已有未提交修改之上继续修复，未重新训练、改写或删除模型资产，未清空数据库。保留既有界面、论文和研究数据。

## 确认及修复

- **运行分析请求竞态**：旧统计范围的结果、错误及 loading 可覆盖新范围。改为复用现有共享资源，各个范围分别保存结果和状态；失败保留有效曲线，正常五分钟更新、失败三十五秒重试、准备中五秒重试。同一资源在途刷新合并。
- **整点窗口结束**：改用按上次完成时间轮询后，整点可能迟于预测过期两分钟才刷新。现在按已结束的目标小时触发一次及时刷新，仍合并在途请求；重复返回相同旧目标不会持续立即循环。
- **真实误差展示**：没有真实样本的小时保持空值，不补成零 MAE。
- **数据库取消安全**：原 SQL 执行线程未结束时，HTTP 超时可先关闭游标及归还连接。现在获取连接、游标、SQL、读取和释放均由同一工作线程负责，取消等待不会释放正在使用的连接。关闭服务时释放 SQLAlchemy 异步引擎，重置认证会话工厂。
- **生产启动依赖**：三个 TF 生产模型使用自己的冻结 Scaler；移除服务容器对旧 38 维 FeatureGenerator/NormalizationAdapter 的无用初始化，避免因未带旧 processed 文件而启动失败。旧模块和研究配置仍保留供离线验证。
- **真实覆盖率**：旧配置的 `...` 正则会匹配任意三个字符，`pass` 也会匹配 password 等标识，导致代码被错误排除。改成整行匹配；原来的零行 100% 不可信。修正后全包行和分支综合覆盖率为 **60.80%**，仍保留 80% 门槛，CI 将报告不达标。功能测试与覆盖率检查分别列明，未降低门槛掩盖缺口。
- **可复现检查**：CI 增加前端测试及生产构建、实际覆盖率 XML 输出，并为认证测试生成随机的隔离 `.env`。模型资产和小型研究配置纳入版本管理。
- **发布前凭据检查**：五个旧 NREL 研究脚本改为读取环境变量；旧 Docker 备份/恢复脚本缺少密码时明确失败，不覆盖外部配置。NREL 密钥已存在于远程历史，新提交不能撤销旧泄漏，应由持有人作废或轮换；本轮未擅自改写历史。
