# ISO-NE 在线预测修复验收记录

> 后续决定：已改为仅本地运行。下文服务器交付事项属于历史记录，不再执行。
> 最新数据口径、时间对齐与测试结果见 [本地运行数据对齐验收](本地运行数据对齐验收-2026-09-23.md)。

## 范围与根因

保留 ISO-NE、现有 TensorFlow 模型和训练资产，不换地区、不训练、不安装或升级依赖。
修复前在线入口分别调用特征构造与模型，缺光伏可能迫使共同窗口倒退；
返回的第一条预测因此可能已经结束，被负荷接口的未来时间检查拒绝，而总览仍画旧曲线。
页面对“整点”与“当前小时”的解释也不一致，网络准备耗时被当作模型推理耗时。

## 本次实现

1. `services/live_forecast.py` 统一自动在线结果，负荷/电价/PV各自状态；60秒缓存及并发合并。
2. 负荷、电价用小时结束标签；PV独立页用小时开始标签；合并曲线显式按结束时间映射。
3. 输入尾部缺失最多6小时，可用昨日相同时段观测补值，并保留来源和日期。历史内部缺口不在此补值。
4. 数据不可用时最多沿用6小时内生成的预测，删除已结束时段，保留原始生成时间和预测起点。不改日期、不补造24个点。
5. 观测、补值和历史回溯标签分离；补值不进入真实观测序列和回溯误差标签。
6. 自动在线请求等待主计算最多约8秒，返回后台准备状态；同一个后台计算不会因页面取消请求而中止。前端准备状态约35秒后重试。
7. 自动在线入库异步执行，预测ID按原始生成标识固定，避免同份结果重复记录；缓存不当作新预测入库。
8. 页面显示观测截至时间、生成时间、分项状态、覆盖区间及部分五分钟采样提示；按分钟边界刷新并隐藏过期点，不插值冒充当前瞬时实测。
9. `inference_time_ms` 只计模型时间，输入准备/网络耗时放入质量元信息。

## 尚不能宣称完成的部分

- **服务器尚未应用这份增量更新，也未通过本次修复后的真实联网验收。** 需按 `deploy/UPDATE-FORECAST.md` 执行并检查三个预测页面。
- 测试验证了降级流程的行为，不等同于验证其预测精度。昨日同小时补输入的精度尚需独立历史延迟实验；前端明确标注。
- 负荷训练特征含历史电价，历史价格数据完全缺失时仍会影响新负荷预测；仅拆分推理不能消除这一训练依赖。
- 长期数据断供、历史内部缺口、模型文件损坏仍可能显示不可用；禁止以演示值伪装恢复。
- 存量数据库/模型是美东无偏移时间；完整夏令时重复/缺失小时改造未包含在本次，不能宣称DST日的实际24小时均已验证。
