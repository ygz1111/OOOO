# 预测评估与输入留档验收

日期：2026-10-03。沿用当前三个生产模型、ISO-NE 与 Open-Meteo 数据源，未训练、替换或删除模型，未修改或删除训练数据。训练环境遵循 [模型训练与验证环境约定](模型训练与验证环境约定.md)。

## 已确认的问题与本轮修改

1. 原在线准确性统计只评价各目标小时最新快照，无法代表固定提前量。现保留原总体口径，并新增提前 1–6、7–12、13–24 小时负荷误差。组内每目标小时取最早生成的快照，同组不会把多次请求重复算为独立样本。同一目标可以出现在不同组，组样本数不能相加；不同组的目标集合也可能不同，不能只按大小推断提前量越长误差越小或越大。
2. 提前量按原始生成时刻到目标小时末的 UTC 实际时长计算：0＜时长≤6、6＜时长≤12、12＜时长≤24。55 分钟的首个预测归入第1组。缓存不改变生成时间，事后生成的预测不参与统计。无法恢复的夏令时歧义时刻排除。
3. 新记录用显式来源标记区分完整输入和估计补齐输入；旧记录没有质量标记时归为未留档。天气插值/异常修正同样标为包含估计输入。真实标签继续通过现有来源校验连接，缺失或未经验证的标签不变成0值。
4. 历史分析→概览复用同次统计请求显示三个提前量分组、独立目标数、MAE/RMSE/MAPE及各输入质量的数量与误差。换周期加载时隐藏旧分组，缺样本显示“暂无已对齐实测”和 `--`。
5. 新增独立压缩输入留档 `backend/cache/forecast_inputs/<内容SHA256>.json.gz`：保存实际使用的天气、来源/采集时间/质量报告、三模型各自过去与未来特征、模型资产签名、模型输入起点、推理完成后的原始生成时间和预测结果。生成时间不再沿用下载开始时刻。归档失败显式反馈，不修改预测或伪造留档成功；破损内容不覆盖。
6. 当前普通天气端点未返回模型运行批次，留档明确保存 `model_run: null` 和 `not_exposed_by_endpoint`，采集时间不能冒充预报发布时间。原始输入快照可以复现实际在线预测，不把事后天气回测改名为在线预测。旧预测未留档时不能补造当时输入。

输入留档与六小时重启缓存分别保存。缓存恢复保留原始生成时间、目标小时和原归档引用；沿用旧预测不新增归档、不重新签发预测。新增文件保留供复现，本轮未添加自动删除策略。

## 离线诊断与电价校准结论

详见 [中文诊断报告](../MMXX/smart-grid/runs/prediction_audit_20261003_final/README.md) 和 `report.json`。

- 分批复用原模型、缩放器、完整验证/测试分区，batch32，无训练。电价只用验证集前段拟合校准参数，并隔离与后段验证共享的目标小时；后段验证筛选后再报告独立测试，测试结果不反向影响选型。
- 原电价测试覆盖率66.93%。两个区间扩宽候选虽然提升测试覆盖，但后段验证的覆盖偏差和区间评分变差，均拒绝启用。P50保持原结果，不能宣称本轮提高了生产精度。
- 负荷高温组（≥86°F）MAE733.65 MW、节假日538.15 MW，整体305.40 MW。现有测试无冬季样本。
- 光伏多云组（八区平均云量＞66%）白天WAPE27.37%，晴天组（≤33%）5.81%。25个完整测试日的峰时间平均绝对误差0.92小时、日能量误差15.52%。这些指标相对于ISO-NE估算分布式光伏参考值，不是电表实测误差。
- 完整离线评估脚本记录耗时22.922秒，是本次离线CPU推理耗时，不能解释为在线启动或接口提速。原数据与模型来源SHA核验无差异。

## 使用与限制

启动仍使用项目根目录 `./start`，页面刷新后在“历史分析→概览”查看提前量统计。完整输入组需要等新预测生成并获得对应真实小时标签，不能给旧记录补造输入质量。

项目根目录运行原输入重放：

```powershell
python backend/scripts/replay_forecast_inputs.py --archive-id <归档编号> --output <新的报告文件>
```

使用本地TensorFlow Python环境；输出文件已存在时拒绝覆盖。归档编号可从预测响应的 `input_quality.input_archive.archive_id` 或重启缓存各组件的原归档引用取得。重放检查模型签名，资产改变后拒绝声称是原模型结果。验证报告见 `docs/evidence/forecast_input_replay_20261003.json`。

本轮实际模型推理验证环境为Windows Python3.11、TensorFlow2.16.1 CPU；用户提供的WSL Python3.10/RTX3050 GPU环境未在本轮验证。正式训练仍优先Colab T4，保存新目录下的 `.keras`、history、metrics；本轮没有启动正式训练，也没有训练导致的梯度/新模型保存加载验证。

未来日期尚无实测时只能验证输入和输出重放，不能提前报告未来误差。历史测试季节、负电价和夏令时覆盖不足的限制继续保留。
