# 本地启动与首次数据加载验收

本轮保留已有大量未提交修改、三个 TensorFlow 模型、ISO-NE 数据源、界面风格和数据库数据。
未训练模型、升级依赖或部署云服务器。项目及父目录未找到适用的 AGENTS.md。

## 确认的问题与处理

- 模型加载后才由页面触发天气、电网输入准备，二者原先顺序等待；新增启动预加载，两个独立输入并行下载，仍复用已有缓存与共享计算。
- 重启丢失内存结果；增加 `backend/cache/live_forecast.json` 原子写入及恢复，保留每项预测原始生成时间、数据来源、目标小时和输入估计状态。
  恢复检查缓存版本、当前模型资产/配置签名、连续24点、有限数值、分位数次序和原生成时间。
  仅展示原生成时间不超过6小时且目标区间尚未结束的部分，标为此前预测；缓存不重新入库。
  过期、损坏、模型变更及无法唯一表达的夏令时目标不恢复，失败不会延长原缓存寿命。
- 更新中有有效预测时立即返回缓存并继续后台计算；无有效预测时仍有8秒请求等待上限，返回明确准备状态。
- 前端准备状态原来35秒后重试，现在5秒重试；完成但分项不可用/缓存降级时35秒重试，正常轮询仍为5分钟。
  隐藏页面继续暂停轮询，返回时及时重试，健康资源不跟随失败资源重复下载。
- 状态栏及首页原来只凭模型加载显示系统正常；现在分别展示准备中、含估计输入、此前预测及分项不可用。
  无曲线时展示准备/重试说明，分项异常显示实际原因；系统状态页明确其卡片是模型服务状态。
- 最新旧日志中图标和Chrome探测地址返回401，预测接口返回200。只对这两个精确路径的GET/HEAD返回204；业务接口继续认证。
- 重启现场发现 Windows 系统端口/CIM 查询被拒绝时脚本误报空闲，再把旧服务响应误判为新启动成功。
  start/stop 共用进程检查工具，查询失败采用 netstat/现有 psutil；启动必须核验新进程或其子进程监听。
  无本项目命令行证据时拒绝终止进程，终止失败保留记录并明确报错。

## 实测

本机真实 MySQL、模型权重、ISO-NE 和 Open-Meteo；北京时间2026-10-01。不同时间网络和数据发布状态不同。

| 场景 | 本次测量 | 结果 |
| --- | --- | --- |
| 修改前，无有效预测缓存，5秒重试探测 | 首个预测请求至24点约26.508秒；前两次约8秒返回准备中 | 24点，三个分项均含估计输入 |
| 修改后，无有效预测缓存，同样5秒重试探测 | 首个预测请求至24点约13.550秒；后台总输入准备及推理16.719秒（预加载已提前开始） | 24点，三个分项均可用 |
| 真实重启 | 日志恢复3项此前预测；新数据在后台16.221秒准备完成 | 新进程PID与监听PID一致，数据库和模型启动通过 |
| 有效结果更新中 | 强制更新请求0.229秒返回24点缓存 | 原生成时间、来源和每个目标小时不变，全部标cached |
| 数据已就绪的浏览器访问 | 状态约1.444秒显示，曲线约4.067秒显示 | 首页到负荷页新增共享请求0，页面异常0 |
| 无认证资源/业务接口 | favicon和Chrome探测204；负荷预测401 | 业务认证保留 |

这些测量不能视为所有时段的固定性能承诺，未测帧率或无缓存浏览器端到端显示时间。
首次仍需真实网络；已有有效缓存也不代表新预测已经生成。

## 使用

继续在项目目录运行 `./start.ps1`，浏览器访问 `http://localhost:3000`。
本轮已启动应用更新后的服务；已有浏览器刷新一次即可。此后正常重启自动恢复有效缓存，不必删除缓存或清空数据库。
缓存目录被Git忽略，模型或配置变更会失效；过期结果会等待外部新资料，不会改时间伪装成新预测。

关键文件：`backend/realtime_api/services/live_forecast.py`、`forecast_cache.py`、`prediction_insight.py`、`frontend/src/contexts/ApiContext.tsx`、`frontend/src/utils/predictionHealth.ts`、`start.ps1`、`stop.ps1`、`scripts/process-runtime.ps1`。
现场日志：`logs/backend.*.log`；首次测量保留在 `docs/evidence/startup-20261001/startup-baseline.*.log`、`docs/evidence/startup-20261001/startup-cold.*.log`。
