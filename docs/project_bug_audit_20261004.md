# 项目明显问题排查与修复记录

日期：2026-10-04（本轮始于 10 月 3 日，跨日完成）

本轮检查了项目说明、适用说明文件、已有 Git 修改、最新日志，以及 Windows 启停脚本、前端请求与认证、后端认证和数据库、预测输入与时间处理、历史回测和缓存。保留原有页面风格、模型权重、训练数据和其他未提交工作，没有训练模型，也没有启动项目常驻服务。

## 确认的问题与修改

| 问题 | 代码或验证证据 | 修复行为 |
|---|---|---|
| 首次没有刷新凭据后，后续登录续期可能永久受阻 | 前端 `refreshPromise` 在提前返回分支不能正确释放；新增用例在修改前复现失败 | 没有刷新凭据时不保存已完成任务，并允许后续登录正常续期 |
| 断网或刷新接口 5xx 会误登出 | 原前端刷新异常统一删除凭据 | 仅明确的 401 身份拒绝清除凭据；网络故障、503 等保留凭据，可再次请求 |
| 旧请求可能影响新登录 | 刷新返回和 GET 去重缺少会话边界，旧任务也能清除新任务 | 按会话版本校验返回结果；切换登录清理请求去重；迟到刷新不能写回旧令牌、登出新用户或覆盖新结果 |
| 注销成功但实际会话未撤销 | 原注销把 JWT 传给数据库 UUID 会话字段；刷新只检查 JWT | 令牌关联真实会话 UUID；受保护请求与刷新验证有效会话；注销后访问和续期均被拒绝，多设备注销保留当前设备 |
| 会话保存失败仍返回登录成功，普通登录时长不一致 | 原保存结果未检查；非“记住登录”会话 30 分钟、访问令牌 12 小时 | 保存失败返回可重试错误；普通会话按访问令牌的 12 小时时长保存；刷新更新存档令牌 |
| 合法数据库密码中的特殊字符导致连接解析错误 | 直接拼接数据库 URL 会把 `@`、`/`、`#` 等当作 URL 结构 | 使用 SQLAlchemy 的结构化 URL，保持用户名、密码及数据库参数原值 |
| 会话列表可能提前 8 小时隐藏有效登录 | 登录用 UTC 存过期时间，视图却与 `NOW()` 比较；本地只读查询确认 `NOW() - UTC_TIMESTAMP()` 为 480 分钟 | 有效会话查询、列表和规范视图统一 UTC 过期比较，并过滤撤销会话、停用用户；闲置时间仍沿用原本同一服务时钟 |
| 近零电价历史回测返回 NaN，可能导致 JSON 响应失败 | 全天真实电价绝对值小于 1 时 MAPE 子集为空 | MAPE 返回空值并说明原因；全部真实标签仍参与 MAE、RMSE 和区间覆盖率；严格 JSON 序列化通过 |
| 单条坏日前记录中断共同数据准备 | 原日前分支直接数值和时间转换，坏记录能使独立可用光伏观测一并丢失 | 逐条校验数值、位置、整点及夏令时歧义，记录排除数量；其他有效数据可保留，缺特征继续明确报错 |
| 失败气象站误标为完整输入 | 失败站 `is_valid=False` 但缺失值计数可为 0，原判定只看缺失与修正数量 | 新预测明确记录失败站、显示站名，并进入已有非完整输入分组；不再标为完整输入，也不混称为插值修正 |
| 启动路径含空格时后端参数被拆开 | 实际 Windows 子进程探针将 `D:\GitHub\Smart Grid\backend` 拆成两个参数 | 引用后端应用目录参数；新增实际子进程验证，目录完整接收 |
| 前端启动器创建异常时可能遗留已启动后端；就绪探测缺少单次超时 | 前端 `Start-Process` 原未捕获创建异常；`curl` 未限制等待 | 创建失败进入后端清理与失败退出，删除失效进程记录；HTTP 探针增加连接及总等待上限 |
| 默认集成测试可能修改当前数据库 | 真实集成模块会自动注册账号，之前仅按模型文件是否存在决定运行 | 真实数据库/外部 API 集成测试默认跳过，必须显式启用；说明需配置隔离测试库 |

生产文件涉及 `start.ps1`、前端 `services/api.ts`、后端 `database.py`、`auth/middleware.py`、`crud/auth_crud.py`、`routers/auth.py`、`tf_split_service.py`、`tf_realtime_feature_provider.py`、`services/live_forecast.py` 及规范会话视图。其余新增或更新主要是专项回归测试。

## 未验证部分与保留的限制

- 本轮遵循此前停止运行的状态，没有执行完整项目启动、真实账号登录注销、浏览器在线端到端流程或云端部署。
- 日志中的 Open-Meteo SSL 连接故障属于实际外部连接问题；恢复逻辑的离线验证通过，但没有重新访问外部服务，不能宣称该连接故障已经消失。
- 没有测量“启动至首次有效预测”或真实接口修改前后耗时，因此本轮不宣称整体提速。上表中的秒数是测试或构建耗时。
- 现有本地 24 小时模型窗口仍对夏令时切换日可靠回测作明确限制；没有修改模型时间契约或假造缺小时数据。
- 气象质量修复作用于新生成预测，现有预测、缓存和归档保留原始生成时间与来源；没有改写历史记录。
- 没有重新打包此前的服务器部署压缩包；本轮交付是当前项目源码。

## 生效方式

在项目根目录正常运行 `./start`，后端和前端均使用修改后的源码。启动中的既有幂等迁移会刷新规范会话视图；本轮没有提前对真实数据库执行它。

浏览器执行 `Ctrl+F5`。旧的非“记住登录”会话如果已经超过原来的 30 分钟，需要重新登录；仍有效的已存档旧令牌保留兼容处理。无需重新训练或替换模型。
