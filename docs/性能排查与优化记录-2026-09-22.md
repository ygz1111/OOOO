# 性能排查与优化记录

检查日期：2026-09-22（北京时间）。范围：前端刷新/切页/绘制、预测接口、气象与 ISO-NE 数据获取、缓存、历史回测、后台同步、状态查询和现有测试。

## 结论（通俗版）

卡顿不只是电脑配置或 ISO 官网的问题。项目之前有不少重复劳动：每次准备预测都重新下载大量历史数据、多个页面分别加载同一张图、状态查询也阻塞服务；同时天气缓存存在过期后仍返回旧数据的错误。画面上的持续动态背景和大面积模糊效果又增加了绘制负担。

这轮优先减少重复劳动，并保留数据时效检查，没有通过永久缓存旧结果来换取“秒开”。未安装或升级依赖，未重训模型，未删除已有业务文件，也未修改模型输入维度。

## 已处理的问题

| 问题与证据 | 本次处理 |
| --- | --- |
| 在线特征每次失效重新抓取整个历史范围，常规计划约 92 个按日请求，不含补缺请求 | 将必要历史缩至 16 天前起；按日期复用原始响应。首次计划约 70 个请求，历史缓存有效时常规更新主要约 10 个近期请求；失败补缺和历史过期仍可能增加请求数 |
| 天气缓存第二次检查没有验证年龄，会长期返回旧天气 | 两层均检查过期时间，合并并发更新；天气全部失败不再用无限期旧数据冒充新数据 |
| 临时整小时复用方案使新天气不能及时进入预测 | 恢复五分钟有效期，天气变化或跨小时重建；近期原始日期缓存也在跨小时时失效 |
| 首页和负荷页分别维护曲线、定时器，切页重新加载；全局刷新遗漏曲线 | 共享数据与一个刷新调度器；合并重复点击、隐藏页面暂停轮询、失败保留旧图并显示错误、单项失败不阻止其他数据定期更新 |
| 不变的历史窗口重复进行 24 次回测 | 同一输入窗口与模型复用回测结果；返回独立结果副本，防止调用方修改缓存 |
| 总览和按日回测缓存从计算开始时计时，慢计算完成后缓存可能已过期 | 从完成时开始计算有效期，总览额外检查小时边界 |
| 状态 GET 每次阻塞采样 CPU，并额外写入监控记录 | 状态接口只读取必要信息，监控采样与持久化保留在后台任务 |
| 实际负荷同步每小时重复抓取 14 天 | 启动及每六小时修订历史，其余周期同步昨天、今天；保留失败重试 |
| 主工作区持续运行背景粒子、卡片背景模糊、曲线重复入场动画 | 主工作区取消持续粒子绘制和卡片背景模糊，保留静态配色；负荷曲线取消重复动画 |
| 电价页一进入就自动执行整天历史回测 | 进入时仅初始化日期范围，回测按用户选择日期或点击按钮运行 |
| 窄屏图表使用固定外框高度，指标换行后图例压到下方卡片 | 外框随内容增高，保留图表最小高度，底部说明允许换行 |
| 净负荷卡片允许相差 90 分钟的数据相减，却标为同一小时 | 使用同一条预测中的负荷和光伏，明确标注“预测净负荷”与目标小时 |
| 上游当前小时已有部分五分钟采样，可能被当作完整小时 | 预测锚点限制在已结束的小时，保留缺样质量说明 |

## 实测（不是性能保证）

使用项目现有 `backend/scripts/stress_first_screen.py`，同时发起三份总览、一份天气和一份负荷预测。本机数据库、模型和外部真实数据源；脚本本身访问 localhost，含连接和网络等待。

| 场景 | 总完成耗时 | 结果 |
| --- | ---: | --- |
| 优化前排查中的一次测量 | 84.2 秒 | 负荷预测返回 500，其余成功；此次 500 的具体原因未单独证实 |
| 本轮优化后重启的首次加载 | 39.5 秒 | 五个请求全部 200；天气 10.5 秒，负荷 37.0 秒 |
| 最终版本再次重启复核 | 36.2 秒 | 五个请求全部 200；天气 10.5 秒，负荷 33.3 秒 |
| 有效缓存内再次刷新 | 2.6 秒 | 五个请求全部 200，重复测量同样约 2.6 秒 |
| 五分钟后浏览器实际更新（后台日志，非脚本总耗时） | 总览 25.2 秒，负荷 20.6 秒 | 均 200；日志确认重新获取六站天气，不是一直返回过期缓存 |

这些是不同时间的现场测量，外部网络、官方数据发布状态及缓存冷热不同，不能将全部耗时差值都归因于代码，也不能承诺每次刷新都只需 2.6 秒。模型计算与下载准备是两回事；页面的模型平均耗时不等于完整网络请求耗时。

## 验证与运行

- 前端新增刷新/重试/隐藏页/切页复用测试；测试共 20 项通过。类型检查与生产构建通过，代码检查没有错误，仍有既存的宽泛类型警告。
- 后端新增天气过期、并发合并、缓存失败处理、历史复用、天气变化、小时边界、完整小时筛选与总览缓存测试。最终完整测试 222 项通过（65.87 秒）；首次运行有一项受系统临时目录权限影响，改用工作区专用临时目录后完整重跑通过。
- 使用 computer-use 电脑操作技能，经浏览器实测首页曲线、首页到负荷页切换、电价预测与按需回测提示；因此发现并修正了窄屏图例重叠，修改后已目视复核。
- 测量日志位于 `logs/performance-backend.stdout.log`；最终运行日志位于 `logs/performance-final-backend.stdout.log`、`logs/performance-final-backend.stderr.log` 及 `logs/performance-frontend.*.log`；下次可继续使用项目原有 `start.ps1` / `stop.ps1`。

## 保留的限制

1. 服务刚启动，或实时缓存过期后，仍需等待天气和电力网站。本轮没有增加跨重启磁盘缓存；重启会失去内存缓存。不存在“任何时候保证秒出新预测”。
2. 较早历史修订最多延后六小时刷新；近期数据仍按五分钟及小时边界更新。空响应和请求失败不存入按日缓存。
3. 当前未结束的一小时不能当作完整小时实况；小时标签还须区分“截至该时刻”与“从该时刻开始”。本轮未更换模型训练时采用的小时口径。
4. 本轮不是重新训练或精度评估，没有声称预测准确率提高。没有长时间运行观测，也没有给出滚动帧率的量化提升。
5. 未对整个已有工作区做清理或提交；原先的修改与删除记录属于已有工作，均予保留。
