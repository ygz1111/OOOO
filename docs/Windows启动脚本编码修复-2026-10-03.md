# Windows 启动脚本编码修复

## 原因与修改

`scripts/process-runtime.ps1` 含中文，原先为不带 BOM 的 UTF-8。Windows PowerShell 5.1 在本机按 GB2312 读取，导致中文乱码、引号误解析和六项连锁语法报错。PowerShell 7 使用 UTF-8，未暴露此问题。

已仅为公共脚本补上 UTF-8 BOM，保留原有内容、进程识别和端口检查逻辑。启动、停止主脚本原本已有 BOM，无须改写。

`scripts/test-process-runtime.ps1` 新增启动相关脚本的编码及语法检查：含非 ASCII 字符时必须有 UTF-8 BOM，即使测试在 PowerShell 7 下执行，也能发现本次兼容性问题。测试自身保持 ASCII，可在 Windows PowerShell 5.1 运行。

## 实际验证

- 修复前真实 `powershell.exe` 5.1 解析准确复现用户六项错误；明确按 UTF-8 读取同一内容后，语法错误为零。
- 修复后 Windows PowerShell 5.1 和 PowerShell 7 的进程检查回归均通过，覆盖 IPv4/IPv6、查询失败、其他项目及旧实例拒绝、新启动进程识别。
- 通过 `powershell.exe` 5.1 实际执行现有 `start.ps1`，退出码为0。模型资产和现有幂等数据库检查通过，前后端新监听进程已核验。
- 浏览器类型请求 `Accept: text/html` 访问前端入口返回200，包含应用挂载点和前端入口；后端及前端代理的状态均为 healthy，模型加载3项。
- 日志确认在线预测准备完成，有效模块3/3，本次输入准备及推理18.2655秒。这是单次启动测量，未作提速对比。

项目已运行，直接访问 http://localhost:3000。以后仍使用 `./start` 或 `.\start.ps1`，无需更换终端。此修复未改模型、业务认证或页面。
